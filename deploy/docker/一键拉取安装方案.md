# DBridge 一键拉取安装体系（客户端分发）

> 目标：让客户在任意 Linux 服务器上，用**一条命令**完成客户端安装，
> 复刻 `bash <(curl -sL xxx.sh)` 的体验，不再需要 scp 手动传文件。

---

## 一、整体架构

```
客户服务器                      你的服务器(dbridge.zzzmxxkj.com)
───────────                     ──────────────────────────────
bash <(curl -sL                nginx 分发路由
  https://dbridge.zzzmxxkj.com   ├── /install.sh      → 一键安装脚本
  /install.sh)                   └── /dist/*.tar      → docker save 镜像包
        │                                    ▲
        │ 1. 检查/装 Docker                   │
        │ 2. curl 下载 tar                    │ publish-dist.sh 上传
        │ 3. docker load                      │ (docker save 导出 + scp)
        │ 4. docker run                       │
        ▼                                    │
   容器跑起来 ────────────────────────────┘
   (数据卷 dbridge-data 持久化)
```

**核心思想**：镜像走 **HTTPS 直下 tar**（不走 Docker Hub，内网/国内友好），
客户侧 `curl` 下载 → `docker load` → 一键 run。闭源产品靠激活码兜底（没授权下不了也白搭）。

---

## 二、三个脚本的职责

| 脚本 | 谁用 | 干什么 |
|---|---|---|
| `install.sh` | **客户** | 客户侧一条命令拉取安装（检查 Docker → 下载 tar → load → run） |
| `publish-dist.sh` | **你（发布方）** | 发布新版：docker save 导出 tar → 上传 install.sh+tar 到服务器 → 配 nginx |
| `update-docker.sh` | **你（发布方）** | 构建新镜像 + 推送到你的服务器（沿用 data 卷升级） |

---

## 三、你的完整发布流程（发一个新版本，例如 1.0.6）

### 第 1 步：改版本号 + 打包

```bash
# 1. 改 pom.xml 的 <version> 为 1.0.6
# 2. 重新打包
build.bat        # 产出 target/dbridge.jar（内含 1.0.6 版本号）
```

### 第 2 步：构建镜像 + 推到服务器

```bash
bash deploy/docker/update-docker.sh 1.0.6 111.231.174.142 ubuntu
```

这一步会：组装 jar+驱动+引擎 → 打 tar → scp 上传 → 服务器 build 成 `dbridge:1.0.6` → 重启容器。

### 第 3 步：发布到分发源（客户可拉取）

```bash
bash deploy/docker/publish-dist.sh 1.0.6
```

这一步会：`docker save dbridge:1.0.6` → 上传 install.sh + tar 到服务器 → 配 nginx 路由。

> ⚠️ 注意：第 3 步依赖本机有 `dbridge:1.0.6` 镜像。如果你在第 2 步是在服务器上 build 的，
> 本机没有这个镜像，可以手动 `docker save` 前先 `docker pull` 或在服务器上执行 save。
> （实际中第 2 步的 update-docker.sh 会把镜像 build 在服务器上，本机没有——
> 见下方「已知问题」）

### 第 4 步：客户一条命令安装

```bash
# 客户在自己的 Linux 服务器上（root）：
bash <(curl -sL https://dbridge.zzzmxxkj.com/install.sh) 1.0.6
```

## 四、服务器端 nginx 路由（首次已配置）

在宝塔 nginx 的 extension 目录下，`publish-dist.sh` 会自动创建
`dbridge-dist.conf`：

```nginx
location = /install.sh {
    root /var/www/dbridge-dist;
    add_header Cache-Control "no-store";
    default_type text/plain;
}
location ^~ /dist/ {
    alias /var/www/dbridge-dist/;
    add_header Cache-Control "public, max-age=3600";
}
```

这样 `/install.sh` 和 `/dist/dbridge-docker-1.0.6.tar` 走本地文件直出，
**不经过** `location ^~ /` 的 27302 反代。
