# DBridge 一键拉取安装体系（客户端分发）

> 目标：让客户在任意 Linux 服务器上，用**一条命令**完成客户端安装，
> 复刻 `bash <(curl -sL xxx.sh)` 的体验，不再需要 scp 手动传文件。

---

## 一、整体架构

```
客户服务器                      你的服务器(dbridge.zzzmxxkj.com)
───────────                     ──────────────────────────────
bash <(curl -sL                nginx 分发路由
  https://dbridge.zzzmxxkj.com   ├── /install.sh      → 一键安装脚本
  /install.sh)                   └── /dist/*.tar      → docker save 镜像包
        │                                    ▲
        │ 1. 检查/装 Docker                   │
        │ 2. curl 下载 tar                    │ publish-dist.sh 上传
        │ 3. docker load                      │ (docker save 导出 + scp)
        │ 4. docker run                       │
        ▼                                    │
   容器跑起来 ────────────────────────────┘
   (数据卷 dbridge-data 持久化)
```

**核心思想**：镜像走 **HTTPS 直下 tar**（不走 Docker Hub，内网/国内友好），
客户侧 `curl` 下载 → `docker load` → 一键 run。闭源产品靠激活码兜底（没授权下不了也白搭）。

---

## 二、三个脚本的职责

| 脚本 | 谁用 | 干什么 |
|---|---|---|
| `install.sh` | **客户** | 客户侧一条命令拉取安装（检查 Docker → 下载 tar → load → run） |
| `publish-dist.sh` | **你（发布方）** | 发布新版：服务器上 docker save 导出 tar → 上传 install.sh + tar → 配 nginx |
| `update-docker.sh` | **你（发布方）** | 构建新镜像 + 推送到你的服务器（沿用 data 卷升级） |

---

## 三、你的完整发布流程（发一个新版本，例如 1.0.8）

### 第 1 步：改版本号 + 打包

```bash
# 1. 改 pom.xml 的 <version> 为 1.0.8
# 2. 重新打包
build.bat        # 产出 target/dbridge.jar（内含 1.0.8 版本号）
```

### 第 2 步：构建镜像 + 推到服务器

```bash
bash deploy/docker/update-docker.sh 1.0.8 111.231.174.142 ubuntu
```

这一步会：组装 jar+驱动+引擎 → 打 tar → scp 上传 → 服务器 build 成 `dbridge:1.0.8` → 重启容器。

> 只改了 jar、引擎没动过时，不必重跑整条流程（它会白拷 300MB 引擎）：
> 直接替换 `deploy/docker/lib/dbridge.jar`，打包 `docker/` 上下文 scp 上去，
> 服务器执行 `docker build -t dbridge:<版本> docker/` 即可，约 40 秒。

### 第 3 步：发布到分发源（客户可拉取）

```bash
bash deploy/docker/publish-dist.sh 1.0.8
```

这一步会：**在服务器上** `docker save dbridge:1.0.8` → 写 `latest.txt` → 维护 `-latest.tar` 软链 →
生成 `.sha256` → 上传 install.sh → reload nginx。

> ⚠️ 本机不需要 Docker。镜像由第 2 步在**服务器**上 build，`publish-dist.sh` 通过 ssh
> 在服务器上执行 `docker save`，再交给 nginx 直出。

### 第 4 步：客户一条命令安装

```bash
# 客户在自己的 Linux 服务器上（root），不带参数 = 装最新版：
bash <(curl -sL https://dbridge.zzzmxxkj.com/install.sh)

# 需要固定版本（回滚用）才带参数：
bash <(curl -sL https://dbridge.zzzmxxkj.com/install.sh) 1.0.8
```

## 四、服务器端 nginx 路由（首次已配置）

在宝塔 nginx 的 extension 目录下，`publish-dist.sh` 会自动创建
`dbridge-dist.conf`：

```nginx
location = /install.sh {
    root /var/www/dbridge-dist;
    add_header Cache-Control "no-store";
    default_type text/plain;
}
location = /dist/latest.txt {
    root /var/www/dbridge-dist;
    add_header Cache-Control "no-store";
}
location ^~ /dist/ {
    alias /var/www/dbridge-dist/;
    add_header Cache-Control "public, max-age=3600";
}
```

这样 `/install.sh`、`/dist/latest.txt` 和 `/dist/dbridge-docker-1.0.8.tar` 走本地文件直出，
**不经过** `location ^~ /` 的 27302 反代。

## 五、当前状态（2026-10-26）

| 项 | 状态 |
|---|---|
| 版本号 | 已升到 **1.0.8** 并打包，jar 内 `Implementation-Version` 与镜像 label 一致 |
| 镜像 | `dbridge:1.0.8`，在服务器上 build（本机无 Docker 也能发） |
| 分发包 | `/var/www/dbridge-dist/dbridge-docker-1.0.8.tar`（437MB）+ `.sha256` + `latest.txt`（=1.0.8） |
| 断点续传 | 客户侧 `curl -C -` 最多重试 5 次，公网 `Range` 请求返回 **206** |
| 完整性 | 下载后校验 sha256，服务器与脚本同源 |
| 客户实测 | 服务器真机跑过完整安装：下载 → sha256 → load → 重建容器，`/api/about/version` = 1.0.8，授权保留 |

> 分发目录**只保留最新一份 tar**（437MB，磁盘有限），旧版本随发布删掉。
> 需要回滚到旧版本时，用对应的旧 jar 重新 build 一次即可。

## 六、遗留

- [ ] **Windows 一键拉取未做**：目前 Windows 仍走 zip 包（`install.sh` 只覆盖 Linux/Docker）。
- [ ] **下载速度受服务器出口带宽限制**：实测单连接约 750 KB/s（约 6Mbps 出口），
      418MB 约 9~10 分钟。拆分并发无效（聚合带宽不变），后续可考虑把 tar 放 COS + CDN。
